01 / The operating model

A task is not a system.

The task is one moving part. Reliable automation needs a complete path from the first bit of context to the moment a failed run becomes better input.

  1. 01

    Context

    What must the system know before it begins—and where does that information come from?

  2. 02

    Work

    What action actually changes the operating state instead of merely generating text?

  3. 03

    Checks

    What has to be true before a person or another system can safely use the result?

  4. 04

    Handoffs

    What decision history, uncertainty, and ownership must move with the work?

  5. 05

    Recovery

    When the automation stops, who takes over—and what gets fed into the next run?

Recovery → ContextFailure is not cleanup after the workflow. It is information the next run needs.

02 / Choose honestly

Sometimes the right answer is not an agent.

I choose based on uncertainty, input stability, judgment, and failure cost—not because an agent makes the project sound bigger.

01

02

03 / What holds up

The handoff is part of the build.

The interesting part is not the first successful run. It is whether the system still makes sense when context moves, a check fails, or a person has to take over.

Checked handoff

Move the context with the work.

A useful handoff preserves what happened, what was checked, what remains uncertain, and who owns the next decision.

Recovery loop

Let failure improve the next run.

When automation stops, recovery should capture the missing context instead of hiding the failure and forcing a person to reconstruct the story.

05 / Start small

Bring the task everyone keeps handing back to you.

Do not start with “add AI.” Start with the recurring task, the context it needs, the check that makes the result usable, and what happens today when it fails.

Four prompts are enough to start:

  1. Name the recurring task and its current owner.
  2. List the context required before work begins.
  3. Define the check that makes an output safe to use.
  4. Describe the handoff and the failure path.
