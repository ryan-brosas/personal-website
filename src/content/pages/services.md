The same task should not pull you back in each week. It may need facts that live
in your head. It may fail when an odd case shows up. A new tool can make that
mess run faster.

We start with one task. You stay in charge of each choice that needs care.

## Does this sound like your week?

- The same task eats your attention every week.
- Key facts are scattered, so someone rebuilds them each time.
- Your automation handles the easy path but leaves you cleaning up.
- An AI test works sometimes, but the team does not trust it yet.
- You want one real workflow fixed before you commit to more.

If one point feels close, there may be a useful first task to fix.

## The scope stays small

We name one task, its start, its end, and the person who owns it. We list the
facts it needs and the calls that must stay with a person.

The first build stays inside that line. It is not a broad AI plan or a push to
add more tools. The task may need an agent, a script, a review step, or a small
change in how the team works.

## Done means your team can run it

One good run is not enough. The handoff must show what ran, what passed, and what
needs help. It also needs a safe stop and clear notes for the next person.

We test the path on real work before the scope grows. If the small loop does not
help, we learn that before more work is built around it.

## Pick the first task

A good first task has a clear start and a result you can check. It happens often
enough to learn from, but it is small enough to test with care.

It may be a report built by hand. It may be a handoff that loses facts. It may
be an AI result that no one trusts yet. You do not need a clean brief before we
talk.
