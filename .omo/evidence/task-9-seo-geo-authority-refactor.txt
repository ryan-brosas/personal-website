CONTRACT
--------
PageMetadata = { title, description, canonical, noindex, og: { title, description, image? } }
- canonical derived ONLY via ROUTE_REGISTRY.canonicalFor(routeId) — no free-form canonicalPath prop
- noindex derived from route.visibility === "noindex"; explicit override wins
- SeoHead emits exactly ONE <link rel="canonical"> and conditional <meta name="robots" content="noindex,follow">
- OG tags parameterized from metadata.og (default to page title/description)

KEY DECISION: noindex,follow (NOT nofollow)
-------------------------------------------
Task brief §4 mentioned "noindex,nofollow" but shell.test.mjs asserts the exact
string content="noindex,follow" (lines 123, 296, 487). The "must not break
shell.test.mjs" invariant (§5) overrides §4 — preserved "noindex,follow".

KEY DECISION: 404 needs an explicit noindex override
----------------------------------------------------
ROUTE_REGISTRY "404" entry has visibility:"public", but 404 must render
noindex,follow. So 404.astro passes noindex as an override — this is exactly
why buildPageMetadata accepts a noindex override.

KEY DECISION: [page].astro content-driven noindex
-------------------------------------------------
The variant shell test builds /about/ with content visibility=noindex and
expects noindex meta. Registry says about=public, so [page].astro passes
noindex={route.visibility==="noindex"} as override — override wins. Variant
test stays green.

ORIGIN PARITY (why switching canonical source is behavior-preserving)
---------------------------------------------------------------------
Old SeoHead used Astro.site.href; astro.config sets site = SITE_ORIGIN ?? "https://example.com".
canonicalFor defaults origin to process.env["SITE_ORIGIN"] ?? "https://example.com".
Identical resolution → canonical output unchanged.
