RECONCILIATION NOTES
- dates shape: §12.2 requires {publishedAt, modifiedAt, reviewedAt, expiresAt}, which
  differs from publishing.ts DateFieldsSchema ({publishedAt, updatedAt, reviewedAt}).
  Since publishing.ts must not change, a new PublicationDatesSchema was defined locally
  in content-schemas.ts.
- "rejects missing visibility": visibility carries the mandated fail-closed
  default("draft"), so an omitted visibility CANNOT be rejected without breaking the
  preserved default. Tests instead assert (a) an INVALID visibility value is rejected
  and (b) omitted visibility DEFAULTS to "draft" — covering the visibility contract
  while honoring the fail-closed default requirement.
- canonicalOverride: modelled as reject-by-default via CANONICAL_OVERRIDE_ALLOWLIST
  (empty today); any value not in the code-owned list fails validation.
- Records flatten SeoFields (title/description at top level) per the task's
  "ServiceRecord/CaseStudyRecord extends PublicationRecord + SeoFields [+ TopicFields]"
  instruction (rather than the plan's nested `seo:` sub-object).
